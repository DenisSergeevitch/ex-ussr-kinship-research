# FamilySearch: точечный поиск и локальный анализ индексов

Читайте при поиске метрической записи по месту или DGS и при анализе уже имеющихся разрешённых материалов. Готовый индекс помогает найти нужный документ; неиндексированные сканы читать по `field-lessons.md`.

Если подключён FamilySearch MCP, структурированные поиск и чтение выполнять по `familysearch-mcp.md`. Проверить фактическую схему поиска: не каждый сервер поддерживает DGS, коллекцию, даты, родителей или просмотр сканов. Для недоступной операции использовать соответствующий браузерный маршрут; наличие MCP не означает, что книга индексирована или доступна целиком.

## Объём и доступ

1. Установить историческое место, приход, конфессию и годы по вопросу. В обычном интерфейсе Search / Images / Catalog найти подходящие книги по месту или DGS и проверить описание нужной части.
2. Использовать существующую законную сессию браузера и штатные инструменты среды для точечного поиска и просмотра. Проверять подходящие записи по именам, родственникам, свидетелям и различающим признакам, сохраняя устойчивую ссылку и минимальный фрагмент только когда это разрешено источником.
3. Соблюдать [условия FamilySearch](https://www.familysearch.org/en/legal/terms), включая требование предварительного письменного разрешения для массового получения данных. Вход, CAPTCHA и ограничения доступа обрабатывать по `browser-and-captcha.md`.
4. В рабочем плане сохранять запрос, просмотренную запись и следующий полезный шаг.

## Просмотр неиндексированных коллекций

Для коллекции без именного индекса используйте дерево просмотра образов или каталог. Проверку места, лет, частей DGS и расхождений описания с титулами выполняйте по `field-lessons.md`, раздел 1, и `search-result-validation.md`: общий диапазон коллекции не устанавливает охват каждого уезда и сословия. Автор [#131](https://github.com/DenisSergeevitch/ex-ussr-kinship-research/pull/131) сообщил о таких расхождениях 31.10–01.11.2026; это наблюдение по просмотренным делам.

В индексированной коллекции отдельные образы могут оставаться без именного индекса. Автор [#160](https://github.com/DenisSergeevitch/ex-ussr-kinship-research/pull/160) сообщил 02.11.2026 о метке «Для этого снимка нет индекса» у части просмотренных образов. Проверяйте охват по конкретному тому или кадру. Если индекс не охватывает нужный участок, отметьте ограничение и при доступности проверьте относящиеся к вопросу образы.

Если том начинается с описи селений и листов, используйте её для адресного перехода и проверьте, что обозначают номера (`field-lessons.md`, раздел 1). Сообщение Image Restricted означает ограничение просмотра конкретных образов: сохраните фактическое сообщение и условия доступа по `browser-and-captcha.md`, не выводя из него недоступность всей коллекции. Отсутствие тома, года или сословия в онлайн-коллекции само по себе не устанавливает сохранность соответствующих документов в архиве.

## Разрешённый фрагмент

Из относящейся к вопросу записи сохранить исходные написания, наблюдённый текст, URL, время и фактический объём. Не требовать сохранения всей выдачи. Пример схемы (значения заменить фактическими):

```json
{
  "url": "https://www.familysearch.org/en/search/record/results",
  "captured_at": "2026-10-26T12:00:00Z",
  "scope": {"description": "Одна подходящая запись по месту и годам", "query": "Фактический запрос"},
  "index_state": "indexed",
  "rows": [{
    "url": "https://www.familysearch.org/ark:/61903/1:1:EXAMPLE",
    "name": "Иван Иванов",
    "text": "Наблюдённый текст записи с упоминанием Марии Петровой",
    "image_url": ""
  }]
}
```

Если отдельного ARK записи не видно, использовать фактическую ссылку изображения `/ark:/61903/3:1:...` и собственный стабильный `observed_id` в строке, например `<DGS>:<кадр>:<номер строки>`. Это локальная метка наблюдения, а не RID источника или доказательство личности. Поле `people` может содержать наблюдённые `name` и `label` родственников и свидетелей; подписи сохранять без преобразования в доказанное родство.

## Неоднозначное состояние

Пустой JSON `{}`, пустая панель, незавершённая загрузка или успешный вход не доказывают доступ к кадру либо отсутствие индекса. Сохранить `index_state: "unresolved"`, `rows: []`, URL, контекст и наблюдённое сообщение в `state_evidence`. При отказе доступа использовать `index_state: "blocked"`. `not-indexed` допустим только при явном сообщении источника, сохранённом в `state_evidence`; это не означает отсутствие людей на скане. Неполные фрагменты всегда имеют `coverage.complete: false` и не закрывают поиск по книге.

## Локальный поиск

Команды выполнять из папки навыка или использовать абсолютный путь. `<дело>` — существующее дело вне навыка.

```bash
python scripts/familysearch.py browser-import <дело>/sources/fs-fragment.json --surnames 'Петрова' --out <дело>/sources/fs-analysis.json
```

Помощник читает только указанные файлы, ищет в наблюдённых именах и тексте, не обращается к FamilySearch и не управляет браузером. Для нескольких фрагментов передать несколько файлов. `--surnames` и `--beacons` принимают Python regex; `--config` — словари метка → выражение в `surnames` и `beacons`. Поиск касается всех сохранённых участников и вариантов имени, а не только основного лица.

## Перенос в дело

```bash
python scripts/register_search.py --case-dir <дело> --input <дело>/sources/fs-analysis.json --research-goal "Проверить кандидатов на родителей"
python scripts/audit_evidence.py --case-dir <дело>
```

Переносятся найденные локальные кандидаты и фактическое покрытие. JSON-снимки сохраняются с SHA-256; повторный импорт не создаёт дубликаты и не затирает ручную оценку, изменившаяся запись получает отдельный снимок. Сбой между записью двух CSV исправляется повтором той же команды.

Автоматический импорт не создаёт людей, утверждения, связи или оценку независимости. Проверить оригинал по ссылке и назначить группу исходного документа; его индекс и скан не являются независимыми подтверждениями. Пустое `independence_group` до проверки даёт ожидаемое предупреждение аудита. Исследовательские файлы и частные примеры в навык не включать.
