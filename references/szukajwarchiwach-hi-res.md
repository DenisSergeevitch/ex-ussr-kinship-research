# Szukaj w Archiwach: загрузка кадров в полном разрешении

Читайте, когда просмотрщик на `szukajwarchiwach.gov.pl` показывает кадр с разрешением, недостаточным для чтения рукописного текста метрической книги, и нужно получить оригинал полного разрешения для проверки спорного имени, графы или подписи. Для разовой справки по номеру акта или уже разборчивого печатного индекса достаточно штатного просмотрщика. Соблюдайте условия портала и шаги `browser-and-captcha.md`; эта техника не отменяет правила источника и не санкционирует массовую выгрузку.

## Что доступно у кадра

- Каждый кадр, выдаваемый просмотрщиком, имеет прямой адрес на CDN `https://photos.szukajwarchiwach.gov.pl/<sha256>_<suffix>`. Суффикс `_mid` — миниатюра (около 380×270), `_max` — оригинал (обычно около 3500×2946). Суффиксы `_mid` и `_max` упомянуты в `seed-sources.md`, строка «Szukaj w Archiwach» (наблюдение [#160](https://github.com/DenisSergeevitch/ex-ussr-kinship-research/pull/160) от 02.11.2026).
- Адрес с `_max` отдаётся анонимно, без сессионной куки, типичным размером 2,5–3 МБ JPEG. Проверено 16.11.2026 на фонде 88/666/0 (Grabowiec православный, 1909).
- Эндпойнт `pobierzplikjpeg/<id>` и кнопка «Pobierz» для анонимного пользователя не работают: первый возвращает ошибку без сессии, вторая — 503 при массовом запросе. Для получения кадра используйте прямой адрес `_max`.

## Как получить sha256 конкретного кадра

1. Открыть страницу единицы (`/jednostka/-/jednostka/<unitId>`) и пролистать до нужного блока миниатюр. Если нужные кадры на другой странице грида миниатюр, переключиться туда перед следующим шагом.
2. В инспекторе сети (DevTools → Network или эквивалент в MCP-браузере) отфильтровать запросы по подстроке `photos`. Миниатюры грида дают URL вида `https://photos.szukajwarchiwach.gov.pl/<64-hex>_mid`.
3. 64-символьный hex между `.pl/` и `_mid` — это sha256 кадра. Порядок URL в сетевом логе соответствует порядку кадров в DOM грида. Для кадра N на странице взять N-й хэш.
4. Полученный хэш подставить в адрес с `_max` и скачать штатным клиентом:

   ```bash
   HASH="7681ae73eb316941e9b4f56355612e7cc8dcc46a6d0f79391a275b0f613d2a44"
   OUT="scan17-akt30.jpg"
   curl -sS -o "$OUT" "https://photos.szukajwarchiwach.gov.pl/${HASH}_max"
   ```

5. Полученный файл сохранять как исходный кадр (см. `metric-books-scans.md`, раздел «Бледные страницы», про хранение исходника отдельно от обработанных копий).

## Что не делать

- Не использовать скриншот окна просмотрщика как основной источник: в штатном окне около 1568×698, этого недостаточно для рукописных граф метрической книги. Скриншот подходит только для черновой инспекции состава страницы перед загрузкой `_max`.
- Не обращаться к `pobierzplikjpeg/<id>` через `curl` без сессионной куки: запрос без входа возвращает ошибку, а воспроизводить сессию из браузера за пределами разрешённого пользователем сценария не нужно.
- Не нажимать кнопку «Pobierz» массово для анонимного аккаунта: сервер отдаёт 503 и это не способ получить кадры. Для последовательной загрузки нужных кадров работайте по шагам выше, с интервалами, соразмерными объёму.

## Передача найденного

Как и для других источников, в `artifact-register.csv` сохранять архивный шифр, номер кадра, URL страницы единицы и URL `_max` как прямую ссылку на исходник. Локальная копия — рабочий файл, URL `_max` — устойчивая ссылка для повторной проверки. Для чтения самого кадра следовать `metric-books-scans.md`.
