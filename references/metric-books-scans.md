# Чтение сканов метрических книг

Выберите режим по запросу. Для расшифровки отдельной страницы или записи достаточно ответа с локатором и оговорками о читаемости. При поиске по книге сообщайте находки и фактический охват. Используйте уже заведённые материалы дела, если они нужны для задачи.

## Чтение страницы или записи

- По общему виду страницы определите графы, номера и границы нужной записи. Если акт продолжается на другой стороне разворота или соседнем кадре, сопоставьте заголовки и номер. Для мелкого текста откройте увеличение с достаточным контекстом для привязки имени и роли к строке. Если пользователь просит прочитать всю страницу, сверка перечня актов с изображением помогает заметить пропущенную запись.
- При подозрении на перенос слова сопоставьте конец строки с началом следующей, даже если знака переноса нет. Для спорной буквы, особенно заглавной, сравните различимые штрихи с ясными примерами той же руки для правдоподобных чтений. Если образцов мало, сохраните варианты. Прежнее чтение семьи может влиять на новые расшифровки. Каждую существенную запись читайте по её собственным штрихам и отмечайте, где на чтение повлиял известный вариант. Различайте имя, отчество и фамилию по полной записи и её графам. Исходное написание, нормализацию и восстановление по другому документу показывайте раздельно.
- Передайте видимую часть слова и отметьте, где чтение сомнительно, текст неразборчив или поле отсутствует. Предложенный пользователем вариант проверьте по различимым штрихам и сохраните неопределённость, если их недостаточно. Порядок повторной проверки спорного чтения описан в `field-lessons.md`, раздел 1, «Проверка визуального чтения».
- Укажите предоставленный или видимый локатор: файл, страницу PDF, лист или кадр, номер акта. Для даты учитывайте отдельные поля рождения, крещения, смерти и погребения, а при необходимости проверяйте заголовок раздела по изображению. По краткому запросу достаточно нужных полей, для дословной выписки сохраняйте структуру и исходную орфографию, насколько позволяет скан.

## Поиск по книге

По титулу, опорным кадрам и структуре книги определите подходящие разделы, годы и графы. Выбирайте их по вопросу. В выбранном охвате сохраняйте существенных кандидатов, включая однофамильцев, которых ещё предстоит различить. Поисковая лента или OCR помогают выбрать кадр для проверки. Важную находку сверяйте по полному изображению записи с нужным контекстом. Сохранение образов и работа с обзорными лентами описаны в `field-lessons.md`, раздел 1.

Если обзорная лента, OCR или миниатюры оставили без находки узкое, хорошо обоснованное окно, проверьте, где первый просмотр мог пропустить запись. Увеличение особенно полезно для бледных строк и непривычной формулы родителей, например когда мать названа только как жена указанного человека. По устройству книги проверьте границы нужного раздела. Запись о рождении может стоять уже в следующем разделе по дате крещения (`field-lessons.md`, раздел 1, «Разделите даты»). Если окно опирается на рождения других детей, сверяйте относящиеся к вопросу записи по `field-lessons.md`, раздел 8. Подробное чтение узкого участка и расширение поиска выбирайте по ожидаемой пользе и доступности.

При передаче результата различайте беглый отбор, подробное чтение и пропуски. Укажите реально просмотренные разделы, кадры и графы, а также нечитаемые места. Для длительного поиска сохраняйте следующий участок в существующем плане. Порядок фиксации охвата и отрицательных результатов описан в `research-coordination.md`, раздел «Длительное чтение сканов», и `evidence-protocol.md`, раздел «Отрицательные результаты».

## Машинное распознавание серии

Если у длинной серии нет машинного текста, её можно распознать самостоятельно и использовать результат для отбора кадров. Локально работают открытые модели строк, например [achimrabus/crnn-ctc-russian](https://huggingface.co/achimrabus/crnn-ctc-russian): русская рукопись, печать и машинопись XVIII–XX веков, включая дореформенную орфографию, лицензия Apache-2.0. Модель читает отдельные строки, поэтому сначала нужна разметка строк на странице. Публичные модели [Transkribus](https://www.transkribus.org/models) для русской рукописи работают в облачном сервисе с месячным лимитом и платой за страницы; перед загрузкой сканов проверьте правила источника и согласие пользователя на передачу материалов (`privacy-and-safety.md`). Заявленная точность модели относится к её проверочному набору. На конкретной серии её стоит проверить по нескольким записям, уже прочитанным по изображению.

- Распознанный текст — наводка для выбора страниц. Ищите основы и обоснованные варианты (`ex-ussr-locale-guide.md`, разделы 3–4) с допуском ошибок распознавания. Редкая фамилия может не распознаться, хотя имена и приписка в той же записи прочитаны. Поэтому полезно искать одновременно несколько слов ожидаемой записи, например имя отца, имя ребёнка и приписку, и смотреть сначала страницы с наибольшим числом совпавших терминов. Короткие основы дают много случайных совпадений. `scripts/htr_search.py` выполняет такой поиск по PAGE XML, ALTO, JSON или TXT, по одному файлу на страницу.
- Найденную запись читайте по изображению по разделам выше. Машинное чтение и проверка того же изображения остаются одной документальной цепочкой (`evidence-protocol.md`, раздел «Независимость»).
- Пустой результат машинного поиска не устанавливает отсутствия записи. В журнале отличайте машинный отбор от просмотра: укажите модель и версию, разметку строк, термины, допуск, распознанные страницы и страницы без текста. Для отрицательного вывода по обоснованному окну просмотрите изображения (`evidence-protocol.md`, раздел «Отрицательные результаты»).

## Загрузка кадров и указателей

Готовность содержимого просмотрщика и действия при сбое проверяйте по `browser-and-captcha.md`, раздел 2, «Загрузка кадров и указателей». В охват включайте фактически просмотренные фрагменты, сохраняя пропуски по порядку выше. Если пользователь поручил поиск только по индексу, соблюдайте этот объём и учитывайте незагрузившиеся карточки как непроверенные.

### Разрешение и привязка изображения

Если штрихов для чтения не хватает, проверьте увеличение и доступную загрузку выбранного кадра. При нескольких вариантах изображения выберите тот, где нужные детали различимы. Размер окна просмотрщика, число пикселей и название варианта помогают выбрать копию; качество проверяйте по самому фрагменту. Читаемый снимок экрана или фрагмент можно использовать в пределах правил копирования источника, сохранив его охват.

Для адреса изображения из просмотрщика или его сетевого журнала установите связь с выбранной миниатюрой и кадром по доступным атрибутам, номеру и содержимому. Сопоставьте заголовок, пагинацию, номер акта или другие видимые признаки. Порядок запросов в журнале сам по себе не устанавливает порядок кадров. Если источник использует варианты адреса для разных разрешений, проверяйте полученный вариант тем же способом. Сохраните ссылку на единицу хранения, локатор кадра и фактический адрес полученной копии. Формат адреса, доступность и происхождение версии требуют проверки на выбранном материале. SHA-256 сохранённого файла вычисляйте по его байтам.

## Бледные страницы

Храните исходный файл отдельно. Если обычного увеличения недостаточно, попробуйте мягкое изменение контраста или просмотр отдельного цветового канала на копии нужного фрагмента. Сравните обработанную версию с исходником: чрезмерная резкость, бинаризация и генеративная обработка могут убрать тонкие штрихи или добавить ложные детали. Если различимых следов всё ещё мало, отметьте пробел или выберите доступную копию лучшего качества. Инструмент и объём обработки выбирайте по читаемости и задаче.
