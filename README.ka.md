**მტკიცებულებებზე დაფუძნებული გენეალოგიური უნარი AI აგენტებისთვის (Codex, Claude Code და სხვა Agent Skills გარემოები).** ის აგენტს აქცევს ოჯახის ისტორიის ყურადღებიან მკვლევრად ყოფილი სსრკ-ის, საბჭოთა კავშირისა და რუსეთის იმპერიის ტერიტორიებზე. აგენტი კითხულობს საეკლესიო წიგნებსა და სამოქალაქო აქტების ჩანაწერებს, სამხედრო, დეპორტაციისა და რეპრესიების საქმეებს, აგრეთვე არაინდექსირებულ საარქივო სკანებს. ყოველი აღმოჩენის წარმომავლობა მიკვლევადია; ჩანაწერები გამიჯნულია ინტერპრეტაციისგან და ნათლად არის ნათქვამი, რა არის დამტკიცებული და რა — არა.

მოიცავს თხუთმეტივე ყოფილ საბჭოთა რესპუბლიკას: რუსეთს, უკრაინას, ბელარუსს, მოლდოვას, ესტონეთს, ლატვიას, ლიეტუვას, საქართველოს, სომხეთს, აზერბაიჯანს, ყაზახეთს, ყირგიზეთს, ტაჯიკეთს, თურქმენეთსა და უზბეკეთს. არქივები შეირჩევა მოვლენის დროინდელი იურისდიქციისა და ჩანაწერების ამჟამინდელი მფლობელის მიხედვით; რეგიონული მაგალითი ადგილობრივ კვლევას ვერ ჩაანაცვლებს.

უნარის ინსტრუქციები რუსულადაა დაწერილი, მაგრამ **აგენტი თქვენს ენაზე გესაუბრებათ**: ინგლისურად, უკრაინულად, რუსულად, პოლონურად, გერმანულად და სხვა ენებზე. წყაროები მოჰყავს ორიგინალური მართლწერითა და თარგმანით, ხოლო საძიებო მოთხოვნებს ჩანაწერების ენებზე ადგენს.

## რას აკეთებს

- **საქმის საწყისი მონაცემები და ფარგლები.** ერთი საკვლევი კითხვა, ცნობილი ფაქტები, ვინ შეიძლება იყოს ცოცხალი და რომელი მოქმედებებია გამორიცხული.
- **გამეორებადი რეესტრები.** პირები, არტეფაქტები, მტკიცებები, ნათესაური კავშირები და ძიების სრული ჟურნალი (CSV), ასევე საბოლოო ანგარიშის შაბლონი.
- **ისტორიული იურისდიქციის მოდელი.** თითოეულ მოვლენას უკავშირებს სახელმწიფოს, პროვინციას, მაზრას, სამრევლოს ან სამოქალაქო რეგისტრაციის დაწესებულებას *მოვლენის თარიღისთვის*, და არა დღევანდელი რუკის მიხედვით.
- **სახელთა ვარიანტების მატრიცები.** რეფორმამდელი რუსული, უკრაინული, პოლონური, რუმინული, გერმანული და იდიშური ფორმები, მამის სახელები, ქალიშვილობის გვარები და ტრანსლიტერაციები.
- **წყაროების სტრატეგია.** ჯერ ორიგინალები, შემდეგ ოფიციალური კატალოგები, საძიებლები და გამოქვეყნებული დოკუმენტთა კრებულები; საგვარეულო ხეები და ფორუმები მხოლოდ შემდგომი ძიების მინიშნებებია.
- **მტკიცებულებათა პროტოკოლი.** მტკიცებებს ენიჭება ახსნადი სტატუსები და არა პროცენტები: `hypothesis`, `single-source`, `corroborated`, `strongly-corroborated`, `contradicted`, `unresolved`. ერთი ჩანაწერის ასლებსა და სარკისებურ ვერსიებს საერთო `independence_group` აქვთ, ამიტომ ისინი დამოუკიდებელ მტკიცებულებებად არასოდეს ითვლება.
- **პირთა იდენტიფიკაცია.** თანამოსახელეებს ცალკე `person_id` უნარჩუნდებათ, სანამ განმასხვავებელი მტკიცებულება არ გამოჩნდება: სახლის ნომერი, მშობლები, ნათლიები, დაბადების ზუსტი თარიღი ან სამხედრო ნაწილი.
- **აუდიტის სკრიპტი.** ამოწმებს მითითებების მთლიანობას და დასკვნების დაწერამდე აღნიშნავს სუსტ დადასტურებას. დამოუკიდებლობის ჯგუფი ითვლება მხოლოდ მაშინ, თუ მას ციტირებული არტეფაქტი ეკუთვნის; დადასტურება მხოლოდ გამოცხადებით ვერ შეიქმნება. ამოწმებს საბოლოო ანგარიშსაც: ყოველი ციტირებული ID რეესტრებში უნდა არსებობდეს და ყოველი სტატუსი მათ უნდა ემთხვეოდეს. შეჯამება აჩვენებს ჯერ დაუდასტურებელ ან გაურკვევლად წაკითხულ მასალას.
- **მოთხოვნები დაწესებულებებისთვის.** ამზადებს და, ნებართვის არსებობისას, უგზავნის მიზნობრივ მოთხოვნებს არქივებს, ბიბლიოთეკებს, უნივერსიტეტებსა და მუზეუმებს ხელმისაწვდომი ელფოსტის ან ოფიციალური ვებინსტრუმენტების გამოყენებით. საჭიროებისას სთავაზობს მხარდაჭერილ საფოსტო ინტეგრაციას ან გასაგზავნად გამზადებულ წერილს. აღრიცხავს შედეგს, თავს არიდებს განმეორებით გაგზავნას და პასუხებს მტკიცებულებებად განიხილავს. იხილეთ [მიმოწერის გზამკვლევი](references/correspondence.md).
- **სახელმწიფო სერვისები.** ირჩევს სამოქალაქო რეგისტრაციის ან საარქივო მოთხოვნის ოფიციალურ გზას, ამოწმებს მიმართვის უფლებასა და შედეგის მიღების წესს ([სახელმწიფო პორტალები](references/government-portals.md)).
- **საბოლოო ანგარიში.** თითოეული ნათესაური კავშირი გაშლილია რგოლ-რგოლ, წინააღმდეგობებით, უშედეგო ძიებებითა და კონკრეტული შემდგომი ნაბიჯებით.
- **ინდექსირებული ჩანაწერების მიზნობრივი კვლევა.** არსებული კანონიერი ბრაუზერის სესიის მეშვეობით პოულობს შესაბამის FamilySearch წიგნებს ადგილის ან DGS-ის მიხედვით, ათვალიერებს კონკრეტულ ჩანაწერებს და ინახავს მხოლოდ წყაროს მიერ ნებადართულ მტკიცებულებათა ფრაგმენტებს. ადგილობრივი დამხმარე ინსტრუმენტები შენახულ ფრაგმენტებში ეძებენ ნათესავებს, მოწმეებსა და სახელთა ვარიანტებს, ინარჩუნებენ კონტექსტსა და ფაილების საკონტროლო ჯამებს. [სამუშაო პროცესი და მოცვის საზღვრები](references/familysearch-indexes.md).
- **დაკავშირებული FamilySearch MCP.** იყენებს დაკავშირებულ სერვერს სტრუქტურირებული ძიების, პროფილების, ნათესავებისა და წყაროებისთვის, ასევე ნებადართული ცვლილებებისთვის ხეში, მკაფიო ფარგლებითა და შედეგის ხელახლა წაკითხვით. ინდექსში ძიებას აცალკევებს არაინდექსირებული სკანების კითხვისგან და ამოწმებს კონექტორის ბრაუზერის, კონფიდენციალურობისა და ჩაწერის რეალურ შესაძლებლობებს. [სამუშაო პროცესი და წვდომის საზღვრები](references/familysearch-mcp.md).
- **პირველი მსოფლიო ომის წყაროების ძიება.** ეძებს GWAR-ის მოხსენებებს, ჰოსპიტლის, ჯილდოსა და სამხედრო ტყვეების ჩანაწერებს პირის ან ადგილის მიხედვით; შენახულ ბარათებში ადარებს დასახლებათა მართლწერას დამახინჯებული ადგილის სახელის გასაშიფრად, შემდეგ პოულობს წყაროს გამოსახულებას. [სამუშაო პროცესი](references/ww1-search.md). ორივე დამხმარე ინსტრუმენტი ავსებს არსებულ არტეფაქტთა რეესტრსა და ძიების ჟურნალს; ისინი ავტომატურად არ ადგენენ პიროვნებას ან ნათესაობას.

## დაყენება

Node.js-ის დაყენების შემდეგ სურვილისამებრ შეგიძლიათ გამოიყენოთ [Skills CLI](https://github.com/vercel-labs/skills):

```bash
npx skills add https://github.com/DenisSergeevitch/ex-ussr-kinship-research
```

CLI საშუალებას გაძლევთ აირჩიოთ აგენტი და ნაგულისხმევად მიმდინარე პროექტში აყენებს უნარს; ყველა პროექტში პირადი გამოყენებისთვის დაამატეთ `-g`. Node.js-ის მიმდინარე მოთხოვნები იხილეთ მის დოკუმენტაციაში.

ალტერნატიულად, დაკლონეთ საცავი პირდაპირ თქვენი აგენტის უნარების საქაღალდეში:

```bash
# Codex
git clone https://github.com/DenisSergeevitch/ex-ussr-kinship-research ~/.codex/skills/ex-ussr-kinship-research

# Claude Code (პირადი უნარები)
git clone https://github.com/DenisSergeevitch/ex-ussr-kinship-research ~/.claude/skills/ex-ussr-kinship-research
```

ერთი პროექტისთვის საქაღალდე მოათავსეთ საცავის შიგნით `.claude/skills/`-ში. სკრიპტებს მხოლოდ Python 3 და სტანდარტული ბიბლიოთეკა სჭირდება; `build_pdf.py`-ს ასევე სჭირდება Chromium-ზე დაფუძნებული ბრაუზერი.

## გამოყენება

აღწერეთ ოჯახის შესახებ საკვლევი კითხვა. აგენტი მუშაობს ხელმისაწვდომი ინფორმაციით და აგრძელებს მუშაობას, სანამ კითხვები ან წვდომის მოთხოვნები პასუხს ელოდება. მაგალითად:

- *„ჩემი დიდი პაპა 1930-იან წლებში ყაზახეთში გადაასახლეს. დამეხმარე მისი მშობლების საეკლესიო ჩანაწერებში მოძებნაში.“*
- *„აი ქორწინების მოწმობისა და ჯარისკაცის ბარათის სკანები. შეამოწმე, ერთსა და იმავე პირს ეხება თუ არა, და ააგე მტკიცებულებათა ჯაჭვი.“*
- *„მოძებნე სამრევლო და შესაბამისი FamilySearch ფირი პოდოლიის სოფლისთვის 1890-იან წლებში და წაიკითხე X გვარის დაბადების ჩანაწერები.“*

საქმის პირადი მონაცემები შეინახეთ უნარის Git სამუშაო ასლის გარეთ. უნარის საქაღალდიდან:

```bash
python scripts/init_case.py --case-dir ~/kinship-cases/my-case --research-question "Who were Maria's parents?" --subject-label "Maria"
python scripts/hash_artifact.py ~/kinship-cases/my-case/scans/marriage-1902.jpg   # SHA-256 ყოველი შენახული არტეფაქტისთვის
```

`init_case.py` უარს ამბობს საქმის შექმნაზე უნარის საქაღალდეში, მათ შორის `--force`-ითაც. დამატებითი დაცვისთვის Git უგულებელყოფს ძველი საქმის საქაღალდეების გავრცელებულ სახელებს; წვლილის შეტანამდე შეამოწმეთ კომიტისთვის მომზადებული ფაილები, განსაკუთრებით არსებული საქმის გადაადგილებისას.

`build_pdf.py`-ს სჭირდება დაყენებული Chrome, Chromium ან Edge (ან `CHROME_PATH`). `--png-dir`-ით გვერდებს შესამოწმებლად PNG-დაც გარდაქმნის, თუ ხელმისაწვდომია `pypdfium2`.

გამოიყენეთ სტატიკური HTML ადგილობრივი ან ჩაშენებული სურათებით. აქტიური HTML და ქსელური სურათის წყაროები უარყოფილია; წყაროს ბმულები დაჭერადი რჩება. წარუმატებელი რენდერისას არსებული PDF შენარჩუნდება.

## საგვარეულო ხე GEDCOM ფორმატში

[GEDCOM](https://gedcom.io/specs/) (`.ged`) გენეალოგიური მონაცემების გაცვლის სტანდარტული ფორმატია. ხის შედგენის ან ექსპორტის მოთხოვნისას აგენტი ამზადებს ადგილობრივ ფაილს წყაროების მითითებებითა და მტკიცებულების სიძლიერის შესახებ შენიშვნებით. თავსებადობისთვის ნაგულისხმევია GEDCOM 5.5.1 UTF-8 კოდირებით, თუ მომხმარებელი სხვა მხარდაჭერილ ვერსიას, მაგალითად GEDCOM 7-ს, არ აირჩევს.

არსებული ხე საწყისი მასალა და ძიების მინიშნებაა; თავისთავად მტკიცებულება არ არის. საწყისი ფაილი ინახება და არ გადაიწერება; დაუდასტურებელი ცნობები და გაურკვევლობა კვლევის საქმეში რჩება. მტკიცებულებათა რეესტრები და ძიების ჟურნალი დასკვნების ძირითად აღრიცხვად რჩება.

პროგრამას მომხმარებელი ირჩევს. აპლიკაციის დაყენება, MCP კავშირის გამართვა და გარე ხესთან ავტომატური სინქრონიზაცია უნარის ფარგლებს სცდება. ვრცლად: [references/gedcom.md](references/gedcom.md).

## პასუხისმგებლიანი გამოყენება

- **ოჯახის ისტორია და არა თვალთვალი.** უნარი უარს ამბობს ცოცხალი ადამიანების ამჟამინდელი მისამართების, ტელეფონების ან ანგარიშების ძიებაზე და ანგარიშებში მათი მონაცემების მოცულობას მინიმუმამდე ამცირებს.
- **წვდომის შემოწმება.** აგენტს შეუძლია ერთხელ სცადოს ნამდვილი CAPTCHA შიდა ბრაუზერის ჩვეულებრივი მართვის საშუალებებით, თუ ეს მხარდაჭერილი და ნებადართულია. მომხმარებლის მოქმედების საჭიროებისას შესაძლებლობის ფარგლებში ხსნის შესაბამის ჩანართს და აწვდის URL-სა და საჭირო მოქმედებას; სისტემაში თავად მომხმარებელი შედის. არ გამოიყენება გარე ამომხსნელი სერვისები, დაცვის, ფასიანი წვდომის, გეოგრაფიული ან მოთხოვნათა სიხშირის შეზღუდვების გვერდის ავლა და გაჟონილი მონაცემთა ბაზები. იხილეთ [ბრაუზერის გზამკვლევი](references/browser-and-captcha.md).
- **თქვენი დოკუმენტები ან დნმ-ის მონაცემები არ აიტვირთება** მესამე მხარის სერვისებში თქვენი აშკარა თანხმობის გარეშე.
- **მგრძნობიარე აღმოჩენები** (დეპორტაცია, რეპრესიები, შვილად აყვანა, დნმ-ის მოულოდნელი შედეგები) გადმოიცემა ნეიტრალურად და მხოლოდ კითხვისთვის აუცილებელ ფარგლებში.
- **ნებადართული მიმოწერა.** უნარს შეუძლია დაწესებულებებისთვის მოთხოვნების გაგზავნა არსებული ინსტრუმენტებით, როცა მომხმარებელმა ეს ნება დართო; უკვე ნებადართულ გაგზავნაზე ხელახლა არ ეკითხება. მხოლოდ საფოსტო ყუთის დაკავშირება არ იძლევა გაგზავნის, დანართების ან ფასიანი სერვისების გამოყენების ნებართვას. გადაამოწმეთ მოქმედი ოფიციალური საკონტაქტო ინფორმაცია და პროცედურა; ავტორიზაციის მონაცემები და საქმის პირადი მიმოწერა უნარის საცავის გარეთ შეინახეთ.

## წვლილის შეტანა

ახალი წყაროები მისასალმებელია `references/seed-sources.md`-ში. შეძლებისამებრ მიუთითეთ გადამოწმებული მფლობელი, იურისდიქცია, კოლექცია, წარმომავლობა, ID-ები, წვდომა, შეზღუდვები და შემოწმების თარიღი; უცნობი მონაცემები აღნიშნეთ და ნუ გამოიცნობთ. მაგალითებში პირადი მონაცემები არ შეიტანოთ.

წყაროების საძიებო დამხმარე ინსტრუმენტები Python-ის სტანდარტულ ბიბლიოთეკასა და საქმის არსებულ რეესტრებს იყენებს. გაუშვით `python3 -m unittest discover -s tests`, რათა სინთეზურ მონაცემებზე შეამოწმოთ ადგილობრივი გარჩევა, GWAR-ის გაგრძელების წერტილები, წვდომის შეცდომები, გაურკვეველი მოცვა და მტკიცებულებათა რეგისტრაცია. FamilySearch-ის მასალების აღმოჩენა და მიზნობრივი ნახვა იყენებს არსებულ კანონიერ ბრაუზერის სესიას; Python-ის დამხმარე ინსტრუმენტები შენახულ ფრაგმენტებს აანალიზებს. კვლევის პირადი ფაილები ამ სამუშაო ასლის გარეთ შეინახეთ.
